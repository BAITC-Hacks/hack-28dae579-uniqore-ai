# Классификатор обращений

Трек 01 «Агентные системы», кейс 01. Репетиция HackAlem.

Скрипт читает обращения из файла и печатает для каждого категорию
(**справка / жалоба / другое**) и черновик ответа на русском языке.

## Что реализовано

- Разбор файла обращений (`messages.txt`) — по одному обращению на строку.
- Классификация в три категории двумя путями: вызов LLM, а если ключа нет или
  LLM недоступен — детерминированные правила.
- Черновик ответа на русском для каждого обращения.
- Вывод в двух форматах: человекочитаемый текст и JSON (`--json`).
- Разбор одного обращения из аргумента: `--text "..."`.
- Обработка крайних случаев: файла нет, файл пустой, строка сверхдлинная,
  текст мусорный, LLM не отвечает.
- Контроль качества ответа LLM: категория, язык и отсутствие выдуманных контактов.
- Ключ читается из `.env` внутри проекта — в окружение системы он не попадает.
- 61 тест на стандартном `unittest`, без обращений в сеть.

## Как устроено

Два файла с кодом, оба читаются за один присест.

| Файл | Ответственность |
|---|---|
| `main.py` | CLI: аргументы, чтение входа, оркестрация, печать, коды возврата |
| `triage.py` | классификация (правила и LLM), сборка черновика, HTTP-клиент |

Путь одного обращения:

```
строка ─► есть ключ LLM и нет --no-llm?
           ├─ да ─► один вызов LLM, строгий JSON {category, reason, reply}
           │         ▼ валидация: категория из списка? ответ непустой? на русском?
           │         ├─ да ─────────────────────────────► результат, источник llm
           │         └─ нет ─┐
           └─ нет ───────────┴─► правила: взвешенный лексический скоринг
                                 ▼
                                 шаблон ответа по категории + тема обращения
                                 ▼
                                 результат, источник rules
```

**Правила.** Три лексикона признаков, у каждого признака свой вес; побеждает категория
с наибольшей суммой. Уверенность — относительный отрыв лидера от второго места.
Ноль совпадений — `другое` с уверенностью 0. Равный счёт — приоритет
`жалоба` → `справка` → `другое`: пропустить жалобу дороже, чем ошибиться в сторону справки.

Признаки общие и не привязаны к пяти тестовым обращениям: «запрос информации или
документа» (`справк`, `как получить`, `какие документы`, `где`, `когда`), «проблема или
недовольство» (`не работает`, `пропал`, `очередь`, `грязно`, восклицательный знак),
«запрос действия» (`записаться`, `перенести`, `предлагаю`, `спасибо`). Что правила
работают на незнакомом тексте, проверяет тест `test_unseen_messages`.

**LLM.** Один вызов на обращение к OpenAI-совместимому `POST /chat/completions` через
`urllib`. По умолчанию — **OpenRouter**: он даёт доступ к моделям разных провайдеров
по одному ключу, а тот же код без правок работает с OpenAI и NVIDIA NIM — меняются
только `LLM_BASE_URL` и `LLM_MODEL`.

Температура 0, строгий JSON-режим, таймаут 20 секунд, до трёх попыток. Учтены две
особенности мультипровайдерного шлюза:

- **не все модели поддерживают `response_format`** — на ответ 400/404/422 запрос
  повторяется уже без строгого JSON-режима;
- **модели любят обернуть JSON** в ```-блок или добавить текст вокруг — разбор это
  терпит и достаёт объект.

Ответ проверяется по четырём правилам: категория из списка, черновик непустой, на
русском и без выдуманных контактов — телефонов, ссылок, адресов почты и длинных
числовых последовательностей. Не прошло — уходим на правила и пишем причину в вывод.
Ошибка 4xx (неверный ключ, нет такой модели) не ретраится, 5xx и сетевые сбои — да.

Промпт отдельно запрещает модели называть расположение объектов, адреса, корпуса,
кабинеты, имена сотрудников, цены и сроки, которых нет в самом обращении. Без этого
ограничения `gpt-4o-mini` уверенно сообщал, что гостевая парковка «расположена рядом
с главным входом» — факт, которого никто не сообщал.

**Черновик ответа.** По LLM-пути его пишет модель. По пути правил — шаблон категории,
в который подставляется тема обращения и маршрут («передали в службу», «ответим за
1 рабочий день»). Шаблоны — это страховка, а не основной путь; см. ограничения.

## Стек и данные

- **Python 3.10+, только стандартная библиотека.** Зависимостей нет,
  `requirements.txt` не нужен, виртуальное окружение не нужно. Проверено на 3.12;
  нижняя граница — 3.10, потому что обработка таймаута опирается на то, что
  `socket.timeout` там стал синонимом `TimeoutError`.
- **Данные** — `messages.txt`, 5 обращений из условия кейса, дословно.
- **LLM (опционально)** — **OpenRouter** по умолчанию, либо любой другой
  OpenAI-совместимый эндпоинт. Настраивается переменными окружения из `.env.example`.

## Установка и запуск

Установки нет. Достаточно Python 3.

```bash
git clone https://github.com/BAITC-Hacks/hack-28dae579-uniqore-ai.git
cd hack-28dae579-uniqore-ai
python3 main.py
```

`messages.txt` и `.env` ищутся рядом со скриптом, поэтому `python3 /путь/к/main.py`
работает из любого каталога. Путь, переданный через `--input`, считается от текущего
каталога.

Ключ не нужен: без него скрипт работает на правилах и не ходит в сеть.

Включить LLM. Ключ кладётся в файл `.env` **внутри проекта**: `main.py` читает его
при запуске, поэтому ключ виден только этому скрипту, а не всем процессам в системе.
`.gitignore` этот файл закрывает.

```bash
cp .env.example .env && chmod 600 .env
```

Впишите в `.env` ключ OpenRouter ([openrouter.ai/keys](https://openrouter.ai/keys))
в строку `LLM_API_KEY=` и запустите `python3 main.py`. Больше ничего настраивать не
нужно: база и модель по умолчанию уже указывают на OpenRouter
(`https://openrouter.ai/api/v1`, `openai/gpt-4o-mini`).

Переменные окружения тоже работают и имеют приоритет над файлом — удобно для разового
прогона с другой моделью или другим провайдером:

```bash
LLM_MODEL=anthropic/claude-3.5-haiku python3 main.py
```

Имя ключа принимается любое из трёх: `LLM_API_KEY`, `OPENROUTER_API_KEY`,
`OPENAI_API_KEY`. В вывод ключ не печатается ни при каких условиях. Если у `.env`
окажутся слишком широкие права, скрипт об этом предупредит.

Аргументы:

| Аргумент | Что делает |
|---|---|
| `--input ФАЙЛ` | другой файл с обращениями (по умолчанию `messages.txt` рядом со скриптом) |
| `--text ТЕКСТ` | разобрать одно обращение из аргумента |
| `--json` | вывести JSON-массив вместо текста |
| `--no-llm` | не обращаться к LLM даже при заданном ключе |

## Проверка основного сценария

Пошагово, «действие → ожидаемый результат». Пункты 1–8 не требуют ни ключа, ни сети.
Каталог запуска значения не имеет.

| # | Команда | Ожидаемый результат |
|---|---|---|
| 1 | `python3 main.py` | 5 блоков: текст, категория, уверенность, черновик на русском. Категории по порядку: справка, жалоба, другое, жалоба, справка. Код возврата 0 |
| 2 | `python3 -m unittest discover -s tests -v` | `OK`, 61 тест, сеть не используется |
| 3 | `python3 main.py --json \| python3 -m json.tool --no-ensure-ascii` | валидный JSON, 5 объектов, у каждого непустой `reply` |
| 4 | `python3 main.py --input /dev/null` | «Обращений не найдено», код возврата 0 |
| 5 | `python3 main.py --input nope.txt` | «Ошибка: файл «nope.txt» не найден», код возврата 2, без трейсбека |
| 6 | `python3 main.py --text "Ыыыы 😀😀"` | категория `другое`, уверенность 0.00, черновик с просьбой уточнить |
| 7 | `LLM_API_KEY=dummy LLM_BASE_URL=http://127.0.0.1:9 LLM_TIMEOUT=2 python3 main.py` | в шапке «LLM недоступен: сеть недоступна…, использованы правила», дальше те же 5 результатов, код 0, ключ в выводе не появляется |
| 8 | `git clone` во временную папку, затем `python3 main.py` | работает сразу, без `pip install` и без `.env` |
| 9 | ключ в `.env`, затем `python3 main.py` | категории и черновики от модели, в строке результата источник `LLM` |

Проверить категории машинно:

```bash
python3 main.py --json | python3 -c "import json,sys; print([r['category'] for r in json.load(sys.stdin)])"
```

Ожидаемый вывод: `['справка', 'жалоба', 'другое', 'жалоба', 'справка']`.

## Известные ограничения

Честно о том, что не сделано и что не проверено.

- **LLM-путь прогнан на живом ключе** 21 сентября 2026 (OpenRouter,
  `openai/gpt-4o-mini`): все 5 категорий совпали с разметкой правил. Это проверка
  работоспособности, а не измерение качества — на пяти обращениях статистики нет.
- **Проверка черновика ловит не всё.** Телефоны, ссылки, почту и длинные числовые
  последовательности отсекаем регулярными выражениями. Выдуманное расположение или
  несуществующий отдел механически не отличить от настоящих — против них работает
  только запрет в промпте, и гарантии он не даёт.
- **Правила рассчитаны на русский язык.** Обращение целиком на английском или казахском
  наберёт ноль очков и попадёт в `другое`. Для кейса это допустимо, для продакшена — нет.
- **Шаблонные ответы не знают фактов.** Без LLM черновик вежливый и маршрутизирующий, но
  не содержит конкретики: ни адреса, ни телефона, ни срока по конкретной справке. Это
  сделано намеренно — выдумывать факты хуже, чем их не давать.
- **Три категории без «не уверен».** При низкой уверенности обращение всё равно получает
  категорию. Порог на ручную проверку напрашивается, но в объём кейса не входил.
- **Классификация без контекста.** Каждое обращение разбирается отдельно: ни истории
  диалога, ни памяти между запусками, ни учёта того, что обращение уже приходило.
- **Один вызов на обращение.** Батчинга нет, на больших файлах LLM-путь будет медленным
  и дорогим.
